# Review of `daily`, 2026-10-17 (second pass)

A read-through of what `fix/review`, `feat/groundwork` and PR 8 (`feat/toggle-keys`) added
on top of `d7bd448`, up to `daily` = `55d0d62`, in the same four parts: core, render and
CI, daemon, GUI. Every bug below was re-checked against the code; the ones that got
numbers are BUGS.md 50–72. Fixes: [review-fixes-2.md](review-fixes-2.md)
(`fix/review-2`, before PR 9). The core and daemon fixes were built and tested in a
scratch copy; the GUI wasn't compiled (no gtk4 on the Mac).

## What's good

- **Config compatibility holds (tested).** Each pre-PR 8 config (the old examples,
  upstream's, and a full one with pages, a folder, dials, `[strip]`, `page_step`,
  brightness `set` and an input mute) was saved with the old code and with `55d0d62`:
  byte-identical. No toggle field leaks into an old config.
- **The first review's bugs are fixed.** 22–24, 26–30, 32–37, 39–44, 46, 47 and 49 hold
  on `55d0d62`; 42 is confirmed on the machine. CI parses and ran green once, and the
  goldens use the bundled font. The rest (25, 31, 38, 45, 48) is below.
- **Groundwork's structure works.** One `Daemon` with `run_input(Source, ..)`, `Runtime`
  that outlives the deck, one end-of-pass `flush`, deadlines through `next_deadline`
  (no busy loop: `wait_for` rounds up, every deadline clears). The hub never writes on
  the loop; a frozen GUI no longer stalls the deck (verified).
- **The watcher is the right shape.** One thread, fully blocking, no tick; state commands
  on runner threads with a bound; volume changes in order, each read back; the in-flight
  follow-up stopped the snap-back on a fast spin. Unit-testable through `Poller`, and
  well tested.
- **PR 8 followed its plan closely.** `OnFace`/`BusyFace` and their field order,
  `state_probe`, `key_status` as the one builder, `Job`, `Toggle`'s wire shape,
  `KeyState` with its page and replay. The deck-side hardware checks all passed.
- **The new process code is careful.** `proc::output_timeout` drains both pipes on
  threads; `Job` reads lines with a cap and kills the whole group; `State` saves whole,
  fsynced, with a per-pid temp file.
- **Design choices that paid off:** `[key.on]` as overrides on the key (minimal TOML),
  exit 75 for busy, the mute source derived from the action, `ActionSlot` with
  `Rc<dyn Fn>` (recursion-ready for PR 12), `face_for` as the one face builder, stamps on
  `clear_cache` only (no disk on a cache hit).

## Problems, ranked

High:

1. **The configurator crashes** on a key drawn "on" without an on face: a stale face tab
   after selecting another key, switching "Two faces" off, a drag, or a hand edit (50).
   → review-fixes-2 tasks 1, 7 (R1).
2. **CI would be red**: clippy 0.1.95 rejects a condition in `render.rs`. `feat/groundwork`
   and `feat/toggle-keys` never ran CI (only `master` pushes trigger it). → task 1.
3. **Service… moves the key to slot 0** and wipes its look (51), and puts the health URL
   into the shell unquoted, so `&` makes the state always "on" (52). → tasks 2, 7.
4. **A slow toggle that never moves stays busy for good** (53). → task 5.
5. **The volume bar can drift** off the real level for good: a failed read, an unwatched
   device, an unplug mid-spin, or mismatched clamps (54; residue of 47). → task 5 (R5).
6. **Bug 25 regressed**: renaming or deleting a page misses a toggle's on action. → task 1
   (R2, one walker).
7. **Bug 45 regressed at start**: after any GUI edit, a restart brings back the config's
   old brightness (the mtime rule from `d9644be`). → task 4 (R3).

Medium:

8. After a replug the configurator shows every toggle off (55); with no deck,
   `Disconnected` goes out every 2 s and the GUI repaints each time. → task 5.
9. A probe re-watched mid-run gets two runs and a spurious warning (56). → task 5.
10. A single Hyprland step still blocks the loop up to 2–4 s; multi-step threads are
    unbounded and unordered (31, partly fixed). → task 6 (R6).
11. The toggle editor: "State from" shows nothing for a mute key (57); the state command
    runs while typed (58); switches don't rebuild and jobs can't get a bar (59). → task 7.
12. Busy bars for `1/4` or `3 of 7` (60); a `$B1` press recolours value and bar (61).
    → tasks 2, 3 (R7, R8).
13. The example's Backup key is never busy, and the docs say "last line" where the code
    reads the first (62). → task 9.
14. `output_timeout` kills only the direct child and waits out the deadline for a
    grandchild's pipe (48, partly fixed). → task 4.

Low:

15. Clearing an On/Busy field creates the face (63); keys the deck lacks are polled, and
    so is everything with no deck (64); a failed runner spawn silences a probe (66).
    → tasks 2, 5.
16. GUI odds: tab buttons not a group (67), repaint every 2 s with no daemon (68), the
    starter ignores `jq` (69), action rows overwrite the group description (70), "New
    page" on an on action restyles the key (72), a strip background picked while the
    config is broken is lost (38, partly fixed). → tasks 7, 8.
17. Render tests that depend on the machine's font and theme (71). → task 3.
18. A held key is repainted as released (65). → PR 13 ([pr13-folders.md](pr13-folders.md), decided).

Design, for later (not bugs, or not fixed here):

19. **Tracked jobs don't really survive a restart.** SIGPIPE is ignored, but the job's
    stdout is a pipe to the daemon; many programs exit on EPIPE, and after a restart the
    key isn't busy and a second press starts a duplicate. task 9 corrects the README;
    re-adopting jobs (output to a file, ids in `State`) is a later PR, with PR 16's "long
    press kills the job".
20. **Background images change only on a reload.** An `~/.config/omarchy/current/background`
    strip (follow the wallpaper) doesn't update when the theme swaps the symlink. Either
    stat the configured images in the 2 s stamp check, or document "save the config".
    Later.
21. **Watcher latency for PR 9.** A volume change can hold the watcher up to ~6 s on
    Omarchy 3 or a hung PipeWire, and a clock read waits behind it. Accepted for PR 9
    (decided); its plan documents it.
22. Smaller: one `Daemon::due(now)` for deadlines before PRs 12–16 add theirs; previews
    at 192 px wrap slightly differently from the deck's 120 px; `StateSaver` has no
    maximum wait; shutdown doesn't join runner threads; `run_tracked` repeats
    `launch_app`'s argv building; `which` exists twice.

Seen and dropped: `keep_toggle_state`'s order (harmless); the busy label's contrast
(user's colours); a 1 px bar offset at 72 px; Lanczos fringes on transparent images; the
Off tab mirroring the deck (as planned); `run_state` leaving a background child (a
`killpg` after reaping could hit a reused group id).

## Did groundwork and PR 8 match their plans?

- **Groundwork:** yes in structure, types and signatures (`proc.rs`, `probe.rs`,
  `is_deck_owned`, `State::save_to`/`load_from`, `Runtime`, `Poller`, `Replay`, writer
  threads). Two changes after the tasks, both recorded in its verification notes: the
  in-flight volume total (good, but 54) and the start-time mtime rule (45's regression).
  One plan item not done: the `$B1` colours (title-only press) were left as one colour
  to keep the goldens (61).
- **PR 8:** close to verbatim. Deviations: the Service URL isn't quoted (52, the plan said
  `shell_words::quote`); "a slow toggle that never starts shows its true state after
  15 s" doesn't happen (53); `face_tab` isn't reset in `select()` as planned (50); the
  Progress bar row isn't offered to `busy_while_running` keys as planned (59); `Value`
  gained serde derives with PascalCase names (R4); the example's LLM block is an escaped
  one-liner, not the plan's multi-line string; `FaceTab`/`LookField`/`StateChoice` landed
  in core (reasonable, tested). The GUI checks were partly skipped; 57 is one of the
  skipped ones ("Follows mute").
