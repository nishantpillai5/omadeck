## The GUI compiles (type-checked on the Mac)

This changes what VERIFY.md says to expect. pkg-config and the GTK libraries aren't on
the Mac, but `cargo check` never links. So a stub `pkg-config` that answers every
version query lets the `*-sys` build scripts pass. The whole GUI crate, bin and tests,
can then be type-checked against the real gtk4 0.11.5 (v4_16), libadwaita 0.9.2 (v1_7)
and glib/gio 0.22.10:

```sh
# $STUB/pkg-config, executable:
#!/bin/sh
for a in "$@"; do case "$a" in --modversion) echo 99.0; exit 0;; --variable*) echo ""; exit 0;; esac; done
echo ""; exit 0

PKG_CONFIG=$STUB/pkg-config cargo clippy -p omadeck-gui --offline --all-targets
```

**Every branch tip type-checks with no errors**, from `fix/review-2` to
`feat/strip-long-press`. Clippy warns, though (bug 78): two `type_complexity` warnings
from `feat/live-keys` on, and a `large_enum_variant` at `feat/strip-long-press`. CI runs
with `-D warnings`, so it is red from PR 9 on. Linking, running the GUI tests and every
click are still for the machine.

## What's good

- **The plans were followed.** The names in the plans' "Names later plans use" sections
  are what the code has. The deviations are small, and each one is written down in
  VERIFY.md. Every reviewer found the plans' "Decided" items in place. These are:
  - one action walker, with the long press last;
  - one Hyprland worker;
  - ctl presses are quiet;
  - replies are never dropped;
  - the busy face wins over live text;
  - Back acts on release;
  - the first non-folder page wins for app pages.
- **Nothing slow runs on the deck loop.** Volume, app volume and media go to the
  watcher, and Hyprland goes to its worker. Spawned commands are reaped on helper threads
  or polled with `try_wait`. Every child process the watcher waits on goes through
  `output_timeout`, which kills the process group.
- **The watcher stays one blocking thread with no tick.** Run ids and cancellation work,
  and a `Leave` window that runs out sends its read. Every volume change is acknowledged
  exactly once, so the in-flight total can't drift. One `pactl` read answers every app
  probe.
- **Config compatibility holds (tested).** A config with every new table round-trips
  through save and parse unchanged: multi, media and delay steps, `[key.on.action]`,
  `[key.live]`, `[[page]] apps`, `[dial.long_press]` and `[dial.live]`.
- **The external parsers are careful.** These cover the edge cases:
  - `/proc/stat` and `/proc/meminfo`;
  - battery fallbacks;
  - `pactl -f json`, where ids and pids may be strings or numbers;
  - playerctl's fields, in µs;
  - Hyprland event lines, where workspace names can have commas and titles can be
    invalid UTF-8.
- **GUI state is sound where it was checked.**
  - RefCell borrows end before the calls that borrow again.
  - Values are set before their handlers are connected.
  - Late results (pickers, focus-out commits) land on the key they were started for,
    through `KeyRef` and `ActionTarget`.
  - The `ActionTarget` matches are exhaustive.
- **The docs match the code**, apart from bug 92: README, CHANGELOG, the example config and
  the site.

## Problems, ranked

High:
- **73. Unplugging the deck while music plays spins the daemon at 100% CPU.**
  `media_due` survives `detach`, so `next_deadline` stays in the past with no deck. It's
  a one-line fix.

Medium:
- **74. Every `omadeckd` ctl call leaks a thread and an fd until the next event.** A
  status-bar script that polls the daemon runs it out of fds in about 17 minutes. After
  that the accept loop spins.
- **75 and 76. Media keys and the player they target.**
  - 75: a seek key does nothing unless something else on the page watches the player.
  - 76: media keys can target a player instance read on another page, which may have
    gone.
  - 94 (low) is the dial-side variant of the same problem.
- **77. The Volume and Brightness dial presets keep `live`,** so the panel keeps showing
  the clock.

## Patterns behind them

- **Features that meet.** Most bugs sit where two PRs' features meet:
  - media and the no-deck loop (73);
  - ctl's short-lived clients and the hub (74);
  - live values and dial presets (77, 101);
  - Back hold and reload (79);
  - title events and app pages (80).

  Each plan was written against the code before it, so later features were checked; the
  places that later features touch weren't.
- **Media targeting is the weakest area** (75, 76, 82, 94, 95). It needs one rule: which
  player a key or dial command goes to, and when a remembered value can be trusted.
- **Two reviewers independently hit the "late commit on another page" class** (99, 104).
  The fix is the one already used for dials and steps: target by `KeyRef`/`ActionTarget`,
  never by index on the current page.
