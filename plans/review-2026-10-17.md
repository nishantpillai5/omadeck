# Review of `daily`, 2026-10-17

A read-through of `daily` = `fix/bugs` (`d7bd448`) against upstream `fb9052f`, our changes
only, in four parts: core (config, actions, audio, state, IPC, docs), render (strip,
backgrounds, CI), daemon (`omadeckd`) and GUI. Every bug below was re-checked against the
code; the ones that got numbers are in [BUGS.md](BUGS.md) 22–49. Fixes:
[review-fixes.md](review-fixes.md) (`fix/review`) for bugs, groundwork.md
(`feat/groundwork`) for the restructuring.

## What's good

- **One renderer really is one.** The GUI preview, `snapshot` and the hardware all draw
  through `render_strip_panel` with the same panel count, so cover-fit and slicing agree.
  The layer order (base, strip slice, dial colour, dial image) matches PR 7's plan, a
  missing file falls back cleanly, and images are never tinted.
- **Config compatibility holds.** Every new field skips when empty; an upstream config
  loads and saves unchanged; old JSON `DeckInfo` still parses.
- **No panics from the device.** Dial indices, tap positions and swipe coordinates are all
  bounds-checked; `steps` is capped at 8; the dirty, pressed and flash vectors are sized
  by the deck's dial count.
- **Threads and channels are tidy.** Audio, brightness, IPC and client threads only; no
  per-event threads beyond the reapers upstream already had. Levels are sent on change
  only.
- **Reload and replug reset what they should.** Levels, watches and selections are
  retained or cleared correctly; `Nav::switch` and `parent` are right and tested.
- **The GUI's own rules are kept.** No `Ref` held across an edit (BUGS.md 4's pattern is
  followed everywhere); every programmatic `set_*` comes before its `connect_*`; timers
  start once; no pollers multiply on reload. Bugs 4, 9–11, 14 and 21a, b, d, e stay
  fixed (21c only for Volume, see 32).
- **Rendering is deterministic** once the font is pinned (ab_glyph in plain `f32`, no
  glyph resampling), so bundling a test font fixes the goldens for good.

## Problems, ranked

High, user-visible or blocking:

2. The strip goldens depend on the machine's font; they fail in CI and on the Mac (23).
   → review-fixes task 1.
3. Every GUI-made page is a folder, so flicks and `page_step` do nothing (24).
   → review-fixes tasks 3, 6.
4. A hand edit of `brightness` never reaches the deck, a regression against upstream (26);

7. The GUI's brightness slider and preview show the config's value, not the deck's (44).
   → groundwork (D1: `Event::Brightness`).

Low:

Design, not bugs (all → groundwork unless noted):

19. The input path is four copies of one block, and callers must remember
    `after_volume`; one `Daemon` + `run_input(Source, ..)` (D3).
20. Daemon state lives in `Deck`, lost on replug and unreachable without a deck (D3).
21. The loop can only wake for HID input; every other source waits up to 100 ms (D4).
22. The audio worker ticks 20×/s forever; PR 8 would copy it; one watcher in
    `probe.rs`/`watch.rs`, not `state.rs` (D5).
23. The GUI polls audio itself, duplicating the daemon (D2).
24. The brightness saver writes a one-field `State`, which would wipe any later field; no
    fsync; not testable on disk (D7).
25. `action_editor` takes nine `impl Fn` generics; PR 12's recursion won't compile (D10).
26. `is_deck_owned()` is unused, misses Brightness, and the list is copied three times
    (D11).
27. Renderer: a `stat` and a 320 KB clone per lookup, no cache sweep, `Level` unclamped,
    `$B1` colours not as PR 3 decided, `DialStatus.level` built in three places (D5, D9).
    `Backdrop::tone_in` → PR 10.
28. Smaller, later: two `Level` types; `run_steps`' folding untestable (PR 10 needs it);
    images decoded on the GTK thread; the strip thumbnail is a 2:1 crop of 8:1; the strip
    preview blurs on HiDPI; `PageStep` from a nested folder (PR 13).

Seen and dropped: Omarchy 3's `HDMI-A-1` fallback (needs the machine to show it's
wrong), silent volume failures without `wpctl` (can't happen on Omarchy), hand-edited
`change = 0`/`200` and duplicate dial indices (edge cases, upstream parity for keys).

## Plan drift

The plans were written before the rebase and the bug pass, and several now describe code
that isn't there:

- **BUGS.md** marked 18 fixed; it isn't (now 29).
- **PLAN.md** "Shared building blocks" puts `Probe`/`Value` in core `state.rs`, which is
  the persisted state file. D5 moves them to `probe.rs`.
- **PR 6**: the hardware check "slider and dial agree after a reload" assumed the dial
  wrote `config.toml`; since bug 5's fix it writes the state file.
- **PR 7**: says SVGs rasterise "straight at the cover scale" and failures are cached
  "like `icon()`"; the code did neither (40, 39).
- **PR 3**: decided accent fill and muted track for `$B1` under `follow_theme`, title-only
  press colour; the code differs and "Decisions to explain" doesn't say so.
- **Rebase plan**: the `folder` flag was to be set only by "New page" from an Open-page
  key; `add_page` set it always (24).
- **PR 8**: `Probe`/`Value` in `state.rs`; `values`/`settle`/`flipped` on `Deck` (lost on
  replug); a 50 ms tick like the audio worker; `Event::KeyState { page: u8 }` (pages are
  `Option<String>` now); mixes `audio::Level` and `render::Level`.
- **PR 9**: "the GUI doesn't poll" — it does (`listen_levels`).
- **PR 10**: its test `run_steps_folds_app_volume` assumes a `fold_steps` that doesn't
  exist.
- **PR 11**: `tag = "cmd"` (it's `"command"`, and changing it breaks the GUI); `do_page`
  (doesn't exist); `handle_command` without `nav`, `wanted_page` and the brightness
  sender; `Reply::State { page: u8, pages: u8 }` and `Action::Page { index, change }`
  (pre-rebase); `key_flash_until = now + KEY_FLASH` (bug 15's fix stores the tap time);
  `Hub::start` must replace upstream's command channel, which the plan says nothing reads.
- **PR 12**: describes three `match act` blocks and a future `dispatch(.., audio, ..)`
  with `do_page`; `dispatch` already exists with `nav` and the brightness sender, no
  `audio`. `is_deck_owned = Page | Brightness` misses `Back` and `PageStep`. "Hyprland
  steps run synchronously as today" becomes a multi-step stall.
- **PR 13**: mostly done upstream (named pages, folders, Back); what's left is the folder
  counting and nested-folder steps.
- **PR 16**: "call the rebase's dispatch" means a fourth copy of the tap block until
  groundwork's `run_input` exists.

All of these are rewritten against `feat/groundwork` before their turn; the cross-plan
decisions (D1–D15) are the reference.
